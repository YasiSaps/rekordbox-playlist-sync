# rekordbox playlist sync (rbsync)

**Update rekordbox playlists in place from M3U / M3U8 files — without deleting and re-importing them, and without rekordbox re-copying your whole USB.**

`rbsync` is a free, open-source command-line tool for DJs using **rekordbox 6 and rekordbox 7** (Pioneer DJ / AlphaTheta) on **macOS and Windows**. Give it an `.m3u` or `.m3u8` playlist file and it adds only the new tracks and removes only the dropped ones from the **existing** rekordbox playlist. The playlist keeps its identity and every track keeps its **hot cues, memory cues, beatgrid, analysis, My Tags and ratings** — so **Sync Manager / USB export only transfers what actually changed** to your CDJ, XDJ or Opus Quad USB stick.

## The problem

You keep a playlist outside rekordbox — generated by a script, an AI assistant, a music app, Serato, Traktor, or a spreadsheet — and export it as **M3U/M3U8**. rekordbox can import it (**File → Import → Import Playlist**), but it can't *update* an existing playlist from a file. So the usual workflow is:

1. Delete the old playlist in rekordbox.
2. Import the new M3U.
3. Sync the USB — and watch rekordbox **remove and re-copy a huge number of tracks** even though only a few changed.

Why? A deleted-and-reimported playlist is a **new playlist** to rekordbox, so Sync Manager tears the old one down and pushes the new one. On top of that, if a path in the M3U is spelled even slightly differently from your library (letter case, accents stored as `é` vs `e + ◌́`, `file://` URLs, backslashes), rekordbox adds the file as a **new, unanalysed track without your cues** — and copies it to the USB again. [Details and evidence →](docs/HOW-IT-WORKS.md)

## What rbsync does

```
your .m3u8  ──►  rbsync plan    compare with the playlist inside rekordbox, show the diff
            ──►  rbsync apply   back up, then add/remove only the changed tracks
                                (same playlist, same track IDs, cues/grids untouched)
            ──►  rekordbox      Sync Manager / Export: only the changed files transfer
```

- ✅ **Incremental** – adds and removes only the difference; `--reorder` optionally matches the file's order.
- ✅ **Keeps everything** – playlist ID, track IDs, hot cues, memory cues, beatgrids, waveforms, analysis, My Tags, ratings, colours, play counts.
- ✅ **Smart path matching** – matches files regardless of Unicode normalization (NFC/NFD), letter case, `file://` URLs, relative paths, or Windows `\` separators. Works with spaces, accents, emoji and non-Latin file names.
- ✅ **No duplicates** – duplicate lines are ignored; if a file already exists twice in your collection, the copy with the most cues is used.
- ✅ **Safe by design** – dry run first, automatic backups, one-command undo, refuses to write while rekordbox is open, never touches your music files. [See Safety](#safety).
- ✅ **macOS and Windows** – plus a drag-and-drop app (macOS) and a right-click *Send to* entry (Windows).
- ✅ **Scriptable** – `rbsync plan --json` for automation and AI-assistant workflows.

## Install

You need **Python 3.9 or newer** and **rekordbox 6 or 7** that has been opened at least once.

### macOS

Open **Terminal** and run:

```bash
curl -fsSL https://raw.githubusercontent.com/YasiSaps/rekordbox-playlist-sync/main/install/install.sh | bash
```

This installs rbsync into `~/.rbsync`, adds the `rbsync` command, and creates the **rbsync Playlist Updater** drag-and-drop app in `~/Applications`. If macOS asks to install the *Command Line Developer Tools* (for Python), click **Install** and run the command again.

### Windows

Install Python from [python.org](https://www.python.org/downloads/windows/) (tick **"Add python.exe to PATH"**) or with `winget install Python.Python.3.12`. Then open **PowerShell** and run:

```powershell
irm https://raw.githubusercontent.com/YasiSaps/rekordbox-playlist-sync/main/install/install.ps1 | iex
```

This installs rbsync into `%LOCALAPPDATA%\rbsync`, adds `rbsync` to your PATH, and adds **rbsync - Update rekordbox playlist** to the right-click **Send to** menu. Open a **new** PowerShell window afterwards.

### With pip / pipx (any platform)

```bash
pipx install git+https://github.com/YasiSaps/rekordbox-playlist-sync
```

Then optionally run `rbsync integrate` for the drag-and-drop app / Send-to entry.

### Check your setup

```bash
rbsync doctor
```

### Uninstall

Run `rbsync integrate --remove`, then delete `~/.rbsync` and `~/.local/bin/rbsync` (macOS) or `%LOCALAPPDATA%\rbsync` (Windows, and remove its `bin` folder from your PATH). Your backups in `Documents/rbsync` are kept until you delete them.

## Quick start

1. **Name the file after the playlist.** `Peak Time.m3u8` updates the rekordbox playlist called **Peak Time**. You can also use `--playlist "Peak Time"`, a `#PLAYLIST:Peak Time` line inside the file, or a folder path such as `--playlist "Gigs / Peak Time"`. Letter case and accents written differently still match, and a typo gets a *Did you mean…?*
2. **Preview** — safe while rekordbox is open:
   ```bash
   rbsync plan "Peak Time.m3u8"
   ```
   ```
   Playlist: "Peak Time" (ID 4243651504, 25 tracks now)
   Playlist file: 32 tracks found in your rekordbox collection

   PLAYLIST CHANGES  (rekordbox database only - no music files are touched)
     + add        10
     - remove     3   (removed from this playlist only; the track stays in your collection)
     = unchanged  22
   ```
3. **Quit rekordbox**, then apply:
   ```bash
   rbsync apply "Peak Time.m3u8"
   ```
4. **Open rekordbox and sync your USB** as usual. Only the 10 new tracks are copied.

Prefer not to type commands? **macOS:** drop one or more `.m3u8` files on **rbsync Playlist Updater** (or right-click → *Open With*). **Windows:** select the files, right-click → **Send to → rbsync - Update rekordbox playlist**. Both show the changes, ask for confirmation, and wait for you to quit rekordbox. Several files are handled one after another.

> **New tracks:** rbsync only adds tracks that are already in your rekordbox collection, so they are analysed properly. Files that aren't are listed as *NOT IN YOUR REKORDBOX COLLECTION* — drag them into rekordbox once, then run rbsync again. Creating a brand-new playlist of brand-new tracks? rekordbox's own **File → Import → Import Playlist** is the right tool for that first import.

## Commands

| Command | What it does |
|---|---|
| `rbsync plan FILE` | Dry run: show what would be added / removed / skipped. Add `--json` for machine-readable output. |
| `rbsync apply FILE` | Back up, then write the changes. rekordbox must be closed. |
| `rbsync sync FILE` | Interactive: preview → confirm → wait for rekordbox to close → apply. |
| `rbsync playlists` | List all playlists, folders and intelligent playlists with their IDs and track counts. |
| `rbsync backups [--prune N]` | List the backups rbsync has made, or delete all but the newest N. |
| `rbsync restore [ID\|latest]` | Undo: put a backup back (the current state is backed up first). |
| `rbsync doctor` | Check Python, pyrekordbox, library location, rekordbox version, permissions and whether an rbsync update is available (`--offline` skips that). |
| `rbsync selftest` | End-to-end test on a **temporary copy** of your library. |
| `rbsync integrate [--remove]` | Add/remove the drag-and-drop app (macOS) or Send-to entry (Windows). |

Options for `plan`, `apply` and `sync`:

| Option | Meaning |
|---|---|
| `--playlist NAME` | Playlist to update, or a path like `"Gigs / Peak Time"` (default: the file's `#PLAYLIST:` line, then the file name). |
| `--playlist-id ID` | Pick one when several playlists share a name (see `rbsync playlists`). |
| `--create` | Create the playlist if it doesn't exist. `--folder NAME` (or `"Gigs / 2026"`) puts it in a folder, creating missing folders. |
| `--reorder` | Also reorder the playlist to match the file. |
| `--case-sensitive` | Treat `Track.mp3` and `track.mp3` as different files (case-sensitive volumes only). |
| `--strict` | Refuse to write if any line of the file was skipped (not in the collection / file not found). |
| `--allow-untested` | Write on a rekordbox version that hasn't been verified yet. |
| `--db PATH` | Use a specific `master.db` instead of auto-detection. |

Exit codes: `0` success · `1` error · `2` blocked (rekordbox running, ambiguous name, cancelled) · `3` unverified rekordbox version.

## Safety

rbsync edits rekordbox's library database, so it is deliberately conservative:

- **Dry run by default.** `plan` never writes. `apply` shows the same report before writing.
- **Automatic backup before every write** of `master.db` (+ `-wal`/`-shm`) and `masterPlaylists6.xml` to `Documents/rbsync/backups`. Undo with `rbsync restore latest`. The newest 30 are kept (set `RBSYNC_KEEP_BACKUPS`, `0` keeps all).
- **Refuses to write while rekordbox is running**, checked by rbsync *and* by pyrekordbox. A lock file stops two rbsync runs from writing at the same time.
- **Ignores deleted items.** rekordbox keeps deleted tracks, playlists and playlist entries in its database (marked as deleted). rbsync never matches, updates or counts them, and keeps track numbers gap-free the way rekordbox does.
- **Only playlist membership changes.** rbsync never adds or deletes tracks in your collection and **never creates, moves, renames or deletes music files**.
- **Verifies after writing** that the playlist contains exactly what the file asked for.
- **Version gate.** Writing is only enabled on rekordbox versions verified end-to-end (including a USB sync). Others need `--allow-untested`.
- **Every run is logged** to `Documents/rbsync/rbsync.log` (rotated at 2 MB).
- **Warns about offline files**: tracks in your collection whose file is missing (moved, or on an unplugged drive) are flagged before you sync.
- rekordbox also keeps its own daily `master.backup.*.db` files.

Set `RBSYNC_HOME` to keep backups and the log somewhere else.

## FAQ

**Will this re-copy my whole USB?**
No — that is the point. The playlist keeps its identity, so Sync Manager only transfers added tracks and removes tracks no other synced playlist uses. Verified on a 2,000-file USB: a +3 / −2 change copied exactly 3 files, deleted 0, re-copied 0. [How to verify on yours →](docs/TESTING.md)

**Does it keep my hot cues, beatgrids and My Tags?**
Yes. Those belong to the track, and rbsync never touches tracks — only which tracks are in the playlist.

**Is this official / safe to use with rekordbox?**
It is unofficial and not affiliated with AlphaTheta / Pioneer DJ. It uses [pyrekordbox](https://github.com/dylanljones/pyrekordbox), a widely used open-source library for the rekordbox database, and adds the safety layer described above. rekordbox has no public API for editing playlists, and XML import cannot update an existing playlist in place.

**Can it import tracks that aren't in rekordbox yet?**
Not on purpose: tracks should be analysed by rekordbox. rbsync lists them so you can drag them in once.

**Does it work with intelligent (smart) playlists or folders?**
It updates regular playlists; rekordbox fills intelligent playlists itself, so rbsync tells you when a name belongs to one. It can create a playlist inside a folder with `--create --folder NAME`.

**I use Cloud Library Sync. Is that OK?**
rbsync writes changes the same way rekordbox does (update sequence numbers included), so they should sync like edits made in rekordbox. This has not been verified yet: try it on a test playlist first and [report](https://github.com/YasiSaps/rekordbox-playlist-sync/issues/new?template=compatibility.yml) what happens.

**How do I update rbsync?**
Run the install command again. `rbsync doctor` tells you when a new version is out.

**Where do the M3U files come from?**
Anywhere: rekordbox/Serato/Traktor/VirtualDJ/iTunes exports, VLC, foobar2000, scripts, playlist generators or AI assistants. Absolute, relative and `file://` paths all work.

**Serato, Traktor, Engine DJ?**
rbsync targets rekordbox only.

## Troubleshooting

| Message | Fix |
|---|---|
| `BLOCKED: rekordbox is running` | Quit rekordbox completely (Cmd+Q / close the window). Check the menu bar / system tray. |
| `there is no playlist called "…"` | The name comes from `--playlist`, the file's `#PLAYLIST:` line, or the file name. Check the *Did you mean* hint, run `rbsync playlists`, or use `--create`. |
| `is an intelligent playlist` | rekordbox fills intelligent playlists automatically. Update a regular playlist instead. |
| `another rbsync … is updating rekordbox` | Wait for the other run to finish. A lock left by a crash is cleared automatically. |
| `N playlists are called "…"` | Use `--playlist-id` with an ID from the list shown. |
| `NOT IN YOUR REKORDBOX COLLECTION` | Drag those files into rekordbox once so they are analysed, then run again. |
| `FILE NOT FOUND ON DISK` | The M3U points at a file that doesn't exist (moved, renamed, drive not mounted). |
| `has not been verified` | Run `rbsync selftest`; if it passes, use `--allow-untested` and please report your version. |
| `Could not find your rekordbox library` | Open rekordbox once, or pass `--db` with the path to `master.db`. |
| Something looks wrong in rekordbox | Quit rekordbox and run `rbsync restore latest`. |

Library locations: macOS `~/Library/Pioneer/rekordbox/master.db` · Windows `%APPDATA%\Pioneer\rekordbox\master.db`.
